# Архитектура

## 1. Общая схема

```
              ┌──────────────────────────────┐
              │           Браузер            │
              │  Next.js (apps/web) — план   │
              │  корзина в localStorage ·    │
              │  3D на React Three Fiber     │
              └──────────────┬───────────────┘
                             │ REST /api/*  (JSON, Authorization: Bearer <JWT>)
                             │ файлы /uploads/*
              ┌──────────────▼───────────────┐        ┌──────────────┐
              │     NestJS (apps/api)        │──SMTP──►    Gmail     │
              │  REST · Swagger · uploads/   │        │ (код сброса  │
              └──────────────┬───────────────┘        │  пароля)     │
                             │ Prisma                 └──────────────┘
              ┌──────────────▼───────────────┐
              │   PostgreSQL 16 (Docker)     │
              └──────────────────────────────┘

        packages/shared (@luxiwood/shared) — общий код API и сайта:
        перечисления, формулы цены, конструктор, этапы заказа, проверка телефона
```

**Кто за что отвечает:**

| Компонент | Ответственность |
|---|---|
| **Next.js** (план) | Весь интерфейс: каталог, страница товара с 3D, конструктор, корзина, кабинет, админка. Цену показывает мгновенно через формулы из `shared`, но окончательную цену всегда берёт у API |
| **NestJS** | Вся бизнес-логика и проверки прав. Единственный, кто пишет в базу. Сам пересчитывает каждую цену, цены от сайта не принимает |
| **PostgreSQL** | Хранит все данные: товары, материалы, заказы, пользователей, настройки |
| **Папка `apps/api/uploads`** | Фото и 3D-модели, загруженные администратором. Раздаётся как статика по `/uploads/...` (см. [media.md](./media.md)) |
| **Gmail (SMTP)** | Письма с кодом восстановления пароля. Без настроек при разработке письмо печатается в консоль API |

## 2. Стек

| Часть | Технология | Почему |
|---|---|---|
| Монорепо | pnpm workspaces | Один репозиторий для API, сайта и общего кода, без лишних инструментов |
| Язык | TypeScript (strict) везде | Типы общие для API и сайта, ошибки ловятся до запуска |
| Бэкенд | NestJS 11 | Модульная структура: один модуль на тему, встроенные guards, pipes и Swagger |
| ORM | Prisma 6 | Типобезопасные запросы, понятная схема, миграции |
| БД | PostgreSQL 16 | Связанные данные (товар → материалы → размеры → заказы) — реляционная БД подходит лучше всего |
| Валидация | class-validator + class-transformer | DTO с русскими сообщениями об ошибках, лишние поля отклоняются |
| Авторизация | JWT (`@nestjs/jwt`), bcrypt | Один токен на 7 дней в заголовке — просто и для сайта, и для Swagger |
| Лимиты | `@nestjs/throttler` | Ограничение регистрации, входа и заказов с одного IP |
| Почта | nodemailer + Gmail | Бесплатно, нужен только пароль приложения Google |
| Загрузка файлов | multer (на диск) | Фото и `.glb` хранятся рядом с API, без внешних сервисов |
| Документация API | `@nestjs/swagger` | `/api/docs` с описаниями и примерами на русском |
| Тесты | Jest + supertest | Unit-тесты формул в `shared`, e2e-тесты API на отдельной базе |
| Локальное окружение | Docker Compose | PostgreSQL поднимается одной командой |
| Сайт (план) | Next.js (App Router), Tailwind CSS, shadcn/ui, Lucide, React Three Fiber | См. [frontend.md](./frontend.md) |

## 3. Структура монорепо

```
TheMebel/
├── apps/
│   ├── api/                    NestJS — см. backend.md
│   └── web/                    Next.js — план, см. frontend.md
├── packages/
│   └── shared/                 @luxiwood/shared — общий код API и сайта
│       └── src/
│           ├── enums.ts        роли, этапы заказа, типы материалов, комнаты, значки, оплата + русские названия
│           ├── types.ts        типы ответов API для сайта
│           ├── validation.ts   телефон +992, slug, цвет #RRGGBB, количество, длина пароля
│           ├── pricing.ts      цена товара, доставка, «Встанет ли у вас?»
│           ├── configurator.ts типы мебели конструктора, диапазоны размеров, опции, формула цены
│           └── order-status.ts правила смены этапов заказа
├── scripts/
│   └── ensure-env.mjs          создаёт apps/api/.env из .env.example при первом запуске
├── docs/                       ТЗ, спек, roadmap
├── docker-compose.yml          PostgreSQL 16, порт 5440
├── pnpm-workspace.yaml
├── tsconfig.base.json          общие настройки TypeScript (strict)
└── package.json                скрипты: dev, build, test, lint, db:migrate, db:seed
```

### Почему `packages/shared` важен

Формула цены описана **один раз** в `pricing.ts`. Сайт считает ею цену мгновенно, пока покупатель щёлкает по тканям, а API считает ею же цену при расчёте и оформлении заказа. Расхождения между «цена на экране» и «цена в заказе» быть не может.

**Правило:** в `shared` кладём только то, что нужно **обоим** приложениям. Никакого кода, зависящего от Nest, Prisma или React. Значения перечислений в `enums.ts` совпадают с `enum` в `schema.prisma`.

`shared` собирается в `dist/` командой `pnpm build:shared`; `pnpm dev`, `pnpm dev:api` и `pnpm test` делают это сами.

## 4. Как сайт общается с API

1. **REST** — все пути начинаются с `/api`, формат JSON. Полный список — [api.md](./api.md).
2. **Авторизация** — токен в заголовке `Authorization: Bearer <токен>`, cookies не используются. Подробнее — [auth.md](./auth.md).
3. **CORS** — API принимает запросы только с адреса из `CORS_ORIGIN` (по умолчанию `http://localhost:3000`).
4. **Файлы** — ссылки вида `/uploads/images/<имя>.jpg` и `/uploads/models/<имя>.glb` открываются на том же сервере, что и API.

## 4.1. Язык

Интерфейс, сообщения об ошибках API и документация — на русском. Позже добавится таджикский, поэтому на сайте тексты интерфейса не зашиваются в компоненты (см. [frontend.md](./frontend.md)). Код — на английском, комментарии в коде — на русском.

## 4.2. Что сознательно НЕ используем

| Технология | Почему не нужна сейчас | Когда понадобится |
|---|---|---|
| **Онлайн-оплата** | По ТЗ оплата при получении (наличные или карта курьеру) | Когда мастерская подключит эквайринг |
| **Облачное хранилище файлов** (S3, Cloudinary) | Фото и моделей немного, они лежат на диске рядом с API | Деплой на сервер без постоянного диска или большой каталог |
| **Redis** | API — один процесс, лимиты `@nestjs/throttler` хранятся в памяти, очередей нет | Несколько экземпляров API |
| **Refresh-токены и cookies** | Один JWT на 7 дней проще; после смены пароля старые токены и так перестают действовать | Если понадобятся короткие токены или вход на сайте через cookies |
| **Микросервисы, GraphQL** | Один модульный NestJS и REST + общие типы проще | — |

## 5. Окружения

| | Локально | Деплой |
|---|---|---|
| Сайт | `http://localhost:3000` (план) | ещё не выбран |
| API | `http://localhost:4000/api` | ещё не выбран |
| Swagger | `http://localhost:4000/api/docs` | выключен, пока `SWAGGER_ENABLED` не `true` |
| PostgreSQL | Docker, `localhost:5440`, база `luxiwood` | ещё не выбран |
| Тестовая база | та же PostgreSQL, база `luxiwood_test` (создаётся тестами сама) | — |

Порт 5440, а не 5432, потому что 5432–5434 на компьютере разработчика заняты другими базами.

## 6. Запуск

```bash
pnpm install
pnpm dev
```

`pnpm dev` по очереди: создаёт `apps/api/.env` (если его нет), поднимает PostgreSQL в Docker и ждёт готовности, собирает `shared`, применяет миграции, заполняет тестовые данные (seed безопасно запускать повторно) и запускает API в режиме `--watch`.

**Правило:** запуск должен оставаться двумя командами — `pnpm install` и `pnpm dev`. Всё, что нужно для работы, добавляется в цепочку `pnpm dev`, а seed не должен ломаться и дублировать данные при повторном запуске.

## 7. Переменные окружения

`apps/api/.env` (создаётся из `apps/api/.env.example`):
```
DATABASE_URL="postgresql://luxiwood:luxiwood@localhost:5440/luxiwood?schema=public"
JWT_SECRET="change-me-to-a-long-random-string"   # без него API не запустится
ADMIN_EMAIL="admin@luxiwood.tj"                  # администратор, которого создаёт seed
ADMIN_PASSWORD="change-me"
PORT=4000
CORS_ORIGIN="http://localhost:3000"              # адрес сайта
SMTP_USER=""                                     # Gmail для писем восстановления пароля
SMTP_PASS=""                                     # пароль приложения Google (16 букв), не обычный пароль
MAIL_FROM=""                                     # пусто — «Luxiwood <SMTP_USER>»
SWAGGER_ENABLED=false                            # в production Swagger включается только при true
```

`apps/web/.env.local` (план):
```
NEXT_PUBLIC_API_URL=http://localhost:4000        # адрес API для запросов и ссылок на /uploads
```

В репозиторий попадает только `.env.example`. Файл `.env` в `.gitignore`.
