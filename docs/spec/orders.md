# Заказы

Код: `apps/api/src/orders/`, правила этапов — `packages/shared/src/order-status.ts`. Эндпоинты — разделы «Заказы», «Мой кабинет», «Админ: заказы» в [api.md](./api.md).

## 1. Путь заказа

```
Сайт: корзина в localStorage (товары + мебель из конструктора)
  │
  ▼
POST /api/orders  — гость или со входом (токен необязателен)
  │  сервер пересчитывает каждую позицию, доставку и итог
  ▼
{ number: "LX-2026-0007", status: "NEW", subtotal, deliveryPrice, total }
  │
  ├── гость:      GET /api/orders/track?number=…&phone=…
  ├── со входом:  GET /api/me/orders, GET /api/me/orders/:number
  └── админ:      GET /api/admin/orders → PATCH /api/admin/orders/:id/status
```

## 2. Оформление — `POST /api/orders`

**Данные покупателя**

| Поле | Правило |
|---|---|
| `customerName` | 2–100 символов |
| `phone` | +992 и 9 цифр, пробелы допускаются; хранится без пробелов |
| `address` | 5–300 символов, адрес в Душанбе текстом |
| `deliveryDate` | необязательно, `ГГГГ-ММ-ДД`, от завтра до +180 дней |
| `payment` | `CASH` (по умолчанию) или `CARD` — оплата при получении |
| `comment` | необязательно, до 500 символов |
| `items` | 1–20 позиций |

**Позиция — либо товар, либо мебель из конструктора** (ровно одно из `productId` и `type`):

| Товар из каталога | Мебель из конструктора |
|---|---|
| `productId`, `mainMaterialId` (обязательны) | `type`, `widthCm`, `depthCm`, `heightCm`, `woodMaterialId`, `finishMaterialId` (обязательны) |
| `colorMaterialId`, `woodMaterialId`, `sizeId` (по умолчанию — значения товара) | `upholsteryMaterialId` (обязателен для мягкой мебели), `colorMaterialId`, `options` (до 10) |
| `quantity` 1–99 | `quantity` 1–99 |

**Что делает сервер:**

1. Каждую позицию проверяет и считает **теми же методами**, что и расчёт цены на сайте: `PricingService.priceProduct` и `ConfiguratorService.priceConfigurator` (см. [pricing.md](./pricing.md)). Ошибка получает номер позиции: «Позиция 2: этот цвет недоступен для товара».
2. Считает `subtotal`, доставку и `total` (`calcOrderTotals`).
3. Если запрос пришёл с токеном — привязывает заказ к пользователю (`userId`), иначе заказ гостевой.
4. Сохраняет заказ, позиции и первую запись истории (`NEW`) одним `create`.
5. Выдаёт номер (см. ниже).

Лимит — 5 заказов в минуту с одного IP, шестой → 429.

## 3. Номер заказа

`LX-<год>-<4 цифры>`, по порядку внутри года: `LX-2026-0001`, `LX-2026-0002`… Следующий номер = последний номер года + 1. Если два заказа пришли одновременно и номер уже занят (ошибка уникальности), сервер пробует следующий — до 5 попыток.

## 4. Снимок позиции

Цены и материалы потом могут поменяться, поэтому в позиции сохраняется всё на момент заказа: `title`, `unitPrice` и `snapshot` (JSON).

Товар из каталога:
```json
{
  "kind": "product",
  "sku": "LX-101", "name": "Диван трёхместный «Ором»",
  "mainMaterial": "Букле", "color": "Карамель", "wood": "Дуб", "size": "210 см",
  "breakdown": [{ "label": "Базовая цена", "amount": 8900 }, { "label": "Материал: Букле", "amount": 0 }]
}
```

Мебель из конструктора:
```json
{
  "kind": "configurator",
  "summary": "Шкаф 160×60×215 см · Орех, Масло-воск · 3 дв., 4 полок · Зеркало на дверь",
  "days": 17,
  "breakdown": [{ "label": "Шкаф 160×60×215 см", "amount": 6743 }]
}
```

Старые заказы не меняются, если потом поменять цены, материалы или удалить размер. Покупателю и в списке заказов `snapshot` не отдаётся — только в карточке заказа для администратора.

## 5. Этапы

```
NEW → FRAME → ASSEMBLY → UPHOLSTERY → DELIVERING → DONE
Принят  Каркас  Сборка    Обивка       В пути       Доставлен

любой незавершённый → CANCELLED (Отменён)
```

| Правило | Пример ошибки (400) |
|---|---|
| только вперёд, этап можно пропустить (у стола нет обивки) | «Нельзя вернуть заказ с этапа «Сборка» на этап «Каркас»» |
| `DONE` и `CANCELLED` — конечные | «Заказ в статусе «Доставлен» больше нельзя менять» |
| нельзя поставить тот же этап | «Заказ уже на этапе «Каркас»» |

Проверка — `orderStatusChangeError(from, to)` из `shared`: сайт может заранее показать только разрешённые кнопки. Каждая смена записывается в `OrderStatusHistory` (кто и когда) в одной операции со сменой статуса. Покупатель видит историю с русскими названиями (`label`).

## 6. Покупатель

| Действие | Правило |
|---|---|
| Отследить без входа | `GET /orders/track?number=&phone=` — номер без учёта регистра. При неверном телефоне — 404 «Заказ не найден. Проверьте номер и телефон», без подсказки, существует ли номер. Ответ без адреса и телефона: номер, этап, дата доставки, итог, позиции, история |
| Мои заказы | только заказы, оформленные со входом; новые сверху, по страницам |
| Мой заказ | чужой номер → 404 |
| Отменить | только на этапе `NEW`, иначе 409 «Заказ уже на этапе «Каркас» — отменить его можно только по телефону мастерской» |

## 7. Администратор

| Действие | Правило |
|---|---|
| Список | фильтры: `status`, `search` (номер, имя или телефон), `dateFrom` / `dateTo` (`ГГГГ-ММ-ДД`, включительно); новые сверху; с числом позиций |
| Карточка | все поля, позиции с материалами и снимком, история, заметка |
| Сменить этап | по правилам из п. 5 |
| Заметка | внутренняя, покупатель не видит; пустая строка удаляет |
| Исправить доставку | имя, телефон, адрес, дата (`null` — убрать дату); у `DONE` и `CANCELLED` — 409 |
| Удалить | только `CANCELLED`, вместе с позициями и историей; иначе 409 |

Статистика (`GET /admin/stats`) считает выручку и продажи без отменённых заказов: выручка и число заказов за этот и прошлый месяц с разницей в процентах, средний чек, заказы в работе (`FRAME`…`DELIVERING`), новые (`NEW`), выручка по месяцам за полгода, продажи по типам мебели, топ-5 товаров, 5 последних заказов.
