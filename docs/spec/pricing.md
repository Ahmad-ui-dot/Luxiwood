# Цены, доставка и конструктор

Все формулы — чистые функции в `packages/shared/src/` (`pricing.ts`, `configurator.ts`), без Nest и Prisma, покрыты unit-тестами.

**Главное правило:** сайт может считать цену этими функциями мгновенно, пока покупатель щёлкает по вариантам, но **окончательную цену всегда считает сервер** — при расчёте (`/pricing/quote`, `/configurator/quote`) и заново при оформлении заказа. Цены, присланные сайтом, не принимаются.

Ошибки входных данных формулы бросают как `PricingError` — API превращает её в 400 с тем же текстом.

## 1. Цена товара — `calcProductPrice`

```
цена за штуку = basePrice
              + доплата основного материала (ткань или дерево, по kind)
              + доплата цвета обивки       (если у товара есть цвета)
              + доплата дерева ножек       (если у товара есть дерево)
              + доплата размера            (если у товара есть размеры)
итого          = цена за штуку × количество (1–99)
```

Ответ содержит расшифровку по строкам (`breakdown`): «Базовая цена», «Материал: Букле», «Цвет: Молочный», «Дерево: Орех», «Размер: 210 см».

**Как сервер выбирает варианты** (`PricingService.priceProduct`):

- товар должен быть активным, иначе 404 «Товар не найден»;
- `mainMaterialId` обязателен;
- каждый присланный вариант должен быть в списке разрешённых у товара и быть активным, иначе 400 («Этот цвет недоступен для товара» и т. п.);
- не присланные цвет, дерево и размер берутся **по умолчанию**: отмеченный `isDefault`, а если отметки нет — первый в списке;
- ответ возвращает итоговый выбор (`selection`), чтобы сайт знал, какие варианты подставлены.

## 2. Доставка — `calcDelivery`, `calcOrderTotals`

```
subtotal      = сумма (цена за штуку × количество) по всем позициям
deliveryPrice = 0, если subtotal ≥ freeDeliveryFrom, иначе deliveryPrice
total         = subtotal + deliveryPrice
```

Значения `deliveryPrice` (150) и `freeDeliveryFrom` (5000) хранятся в настройках, меняет администратор. Сайт берёт их из `GET /api/settings/public`, чтобы показать «до бесплатной доставки осталось …».

## 3. «Встанет ли у вас?» — `checkFit`

Покупатель вводит ширину ниши, сервер сравнивает её с шириной выбранного размера (или `Product.widthCm`, если размеров нет).

```
запас = ширина ниши − ширина товара
```

| Запас | Ответ |
|---|---|
| от 20 см (`FIT_MARGIN_CM`) | `fits: true` — «Встанет: останется N см свободного места» |
| 0–19 см | `fits: false` — «Впритык: останется N см, а нужно хотя бы 20 см на проход и монтаж» |
| меньше 0 | `fits: false` — «Не встанет: не хватает N см» |

Ширина ниши — целое число 1–2000 см.

В каталоге есть родственный фильтр `?maxWidth=` — товары, у которых `widthCm` не больше ширины ниши.

## 4. Конструктор — `calcConfiguratorPrice`

Мебель под свои размеры: диван, кресло, кровать, шкаф, стол. Описание типов — `CONFIGURATOR_TYPES` в `configurator.ts`.

### Типы, размеры, сроки

| Тип | Ширина, см | Глубина, см | Высота, см | Обивка | Срок, дней |
|---|---|---|---|---|---|
| `sofa` — Диван | 140–320 (210) | 80–120 (95) | 75–100 (85) | да | 14 |
| `armchair` — Кресло | 60–110 (82) | 70–100 (84) | 80–110 (92) | да | 10 |
| `bed` — Кровать | 100–220 (170) | 200–230 (210) | 90–130 (110) | да | 14 |
| `wardrobe` — Шкаф | 60–300 (160) | 35–70 (60) | 150–280 (220) | нет | 16 |
| `table` — Стол | 80–260 (160) | 60–120 (90) | 70–80 (75) | нет | 10 |

В скобках — размер по умолчанию. Размеры — целые сантиметры.

### Формула

```
коэффициент = (ширина × глубина × высота) / (объём размера по умолчанию)

основа       = round(цена типа × коэффициент)
+ ткань      = round(доплата ткани × коэффициент)     — только мягкая мебель, обязательна
+ цвет       = round(доплата цвета × коэффициент)     — только мягкая мебель, по желанию
+ дерево     = round(доплата дерева × коэффициент)    — обязательно
+ покрытие   = round(доплата покрытия × коэффициент)  — обязательно
+ опции      = фиксированная цена каждой опции

цена за штуку = вверх до 10 сомони (в расшифровке — строка «Округление до 10 сомони»)
итого         = цена за штуку × количество (1–99)
срок          = срок типа + дни опций
```

Цены типов и опций хранятся в настройках (`configuratorBasePrices`, `configuratorOptionPrices`) и сразу влияют на следующий расчёт.

### Проверки

- размер вне диапазона → «Ширина дивана должна быть целым числом от 140 до 320 см»;
- мягкая мебель без ткани → «Выберите ткань обивки для: диван»;
- шкаф или стол с тканью или цветом → «Шкаф делается без обивки — ткань и цвет не выбираются»;
- опция чужого типа или повтор → 400;
- материал должен существовать, быть активным и нужного типа, иначе «Дерево: материал с ID 5 не найден или отключён».

### Ответ

`{ price, quantity, total, days, summary, breakdown }`. `summary` — строка для корзины и заказа: «Шкаф 160×60×215 см · Орех, Масло-воск · 3 дв., 4 полок · Зеркало на дверь». У шкафа в ней двери и полки:

- двери: `max(2, ceil(ширина / 55))`;
- полки: `floor(высота / 40) − 1`.

`GET /api/configurator/options` отдаёт всё для экрана конструктора: типы с диапазонами, ценой типа и сроком, активные ткани и цвета (только мягкой мебели), дерево и покрытия, опции с ценами.
